Use the hopbox CLI

The hopbox CLI signs in to an install with your browser, and then manages your orgs, API keys, and SSH keys. This guide signs the CLI in to an install on a laptop and runs each kind of command once. reference/cli.md lists every command, flag, file, and exit status.

A person approves the sign-in on the console page /device (console.md). This guide approves it with curl, in the same way as that page does, so it shows each call.

What you need

Section titled “What you need”
  • An install on a laptop with a domain and a signed-in instance admin, as at the end of first-sign-in.md. This guide uses the API on 127.0.0.1:7080 and the domain example.com.
  • The shell function browser of that guide, which calls the API as the console does, with your session cookie.
  • ssh-keygen and python3.

On Linux, use bin/linux_amd64 or bin/linux_arm64.

The URL uses plain http, which the CLI accepts only for a loopback address. A real install uses https://example.com, or the bare domain.

Now be the person at the console. Look up the code, check that the client is your own CLI, and approve it:

If your sign-in is more than 10 minutes old, the approval fails with permission_denied. Sign in again, then approve the same code (cli-and-keys.md).

The CLI polls every 5 seconds, so it sees the approval within a few seconds:

The account had no SSH key, so the login made the key ~/.ssh/hopbox_ed25519 and added it (reference/cli.md). --no-ssh-config leaves ~/.ssh alone.

The CLI stored its tokens in ~/.config/hopbox/credentials.toml, mode 0600, and the install in ~/.config/hopbox/config.toml (reference/cli.md). Ask who you are:

Work in an org

Section titled “Work in an org”

Each command acts in one org. Until you pick one, that is your personal org. Make an org for a team, and make it the active org of the profile:

The star marks the active org. Commands now act in acme. One command can act in another org with --org, by name or UUID, such as hopbox --org Personal org usage. See what the org uses, and invite a colleague:

With an SMTP config, the install also emails the link. With the file mail transport of a dev install, it writes the email to a file on the server instead (reference/mail.md). Ann signs in, and joins with hopbox org join '<link>'. Her account must hold the email of the invitation as a verified email. Then hopbox org member list shows her, and hopbox org member set-role ann@example.org member changes her role.

Make an API key for a script

Section titled “Make an API key for a script”

A script uses an API key, not your CLI sign-in. The key acts as you in the active org:

The secret went to $KEY, and the note went to stderr. The install keeps no copy of the secret. Give the key to the CLI of the script in HOPBOX_API_KEY, and the URL of its install in HOPBOX_URL. The CLI never sends a key to the URL of a profile, which can be another install:

The key works in its own org, acme. No key can make another key, and the status 3 tells a script that the install refused the call. After the last run of the script, revoke the key with hopbox api-key revoke <id>.

Add an SSH key

Section titled “Add an SSH key”

The SSH front door finds your account by your SSH key (ssh.md). The login added ~/.ssh/hopbox_ed25519. To use another key too, add its public key, never the private key:

The comment of the key became its name. hopbox ssh-key add /tmp/hb/id_ed25519 fails with this is a private key. Give the public key, the .pub file, and status 80.

Keep the sign-in alive

Section titled “Keep the sign-in alive”

The access token lives 1 hour, and the refresh token lives 30 days. The CLI trades them for new ones by itself. With --debug, you see each refresh. Mark the access token as ended in the file to force one now:

On Linux, use sed -i without ''. A refresh token works once, and a used one that comes back ends the whole sign-in. So the CLI refreshes under a lock of the config dir. Many commands at once, in many terminals, make one refresh, and the others read the new tokens.

Sign out

Section titled “Sign out”

logout ended the CLI sign-in on the install too, so a copy of its tokens does not work anymore. The profile keeps its URL and its active org, so hopbox login alone signs in again. On a lost laptop, end the sign-in from another device with AccountService/EndCLISignIn (reference/auth-api.md).
