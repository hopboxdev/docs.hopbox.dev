Use the hopbox CLI

The hopbox CLI signs in to an install with your browser. Then it manages your machines, orgs, API keys, and SSH keys. This guide runs each kind of command once against the install https://example.com. Use machines from the CLI covers the machines. hopbox CLI lists every command, flag, file, and exit status.

What you need

Section titled “What you need”
  • The hopbox CLI, installed and signed in to an install, as in Install the hopbox CLI.
  • python3, for one of the examples.

Sign in

Section titled “Sign in”

hopbox login signs in with a device flow. The CLI prints a code and a link. You open the link in a browser where you are signed in to the console, check the code, and click “Approve” (Install the hopbox CLI):

The approval needs a sign-in to the console within the last 10 minutes. After an older sign-in, the page asks you to sign in again, then shows the code again.

The CLI keeps its tokens in ~/.config/hopbox/credentials.toml, mode 0600, and the URL of the install in ~/.config/hopbox/config.toml (hopbox CLI). Ask who you are:

Work in an org

Section titled “Work in an org”

Each command acts in one org. Until you pick one, that is your personal org. Make an org for a team, and make it the active org of the profile:

The star marks the active org. Commands now act in org1. One command can act in another org with --org, by name or UUID, such as hopbox --org Personal org usage. See what the org uses, and invite a colleague:

With an SMTP config, the install also emails the link. The colleague signs in, and joins with hopbox org join '<link>', or opens the link in a browser. Their account must hold the email of the invitation as a verified email. Then hopbox org member list shows them, and hopbox org member set-role user2@example.org member changes their role. Work in a team org covers the roles.

Make an API key for a script

Section titled “Make an API key for a script”

A script uses an API key, not your CLI sign-in. A member key acts as you in the active org:

The secret went to $KEY, and the note went to stderr. The install keeps only a hash of the key, so this is its only copy. Give the key to the CLI of the script in HOPBOX_API_KEY, and the URL of its install in HOPBOX_URL. The CLI never sends a key to the URL of a profile, because a profile can name another install:

The key works in its own org, org1. No key can make another key, and the status 3 tells a script that the install refused the call. After the last run of the script, revoke the key with hopbox api-key revoke <id>.

An org admin or an org owner also makes org keys, with --kind org. An org key is a credential of the org, not of a person. So if its creator leaves the org, the key stays. CLI tokens, API keys, admin API keys, and SSH keys gives the rights of each kind.

Add an SSH key

Section titled “Add an SSH key”

The SSH front door finds your account by your SSH key (Reach a machine over SSH). The login added ~/.ssh/hopbox_ed25519. To use another key too, add its public key, never the private key:

The comment of the key became its name. RSA keys need at least 3072 bits, so Ed25519 is the simple choice. A key works for one account only, so the same key on another account fails with already_exists. hopbox ssh-key add ~/.ssh/id_ed25519 fails with this is a private key. Give the public key, the .pub file, and status 80.

Keep the sign-in alive

Section titled “Keep the sign-in alive”

The access token lives 1 hour, and the refresh token lives 30 days. The CLI trades them for new ones by itself. With --debug, each refresh writes the log line refreshed the CLI tokens to stderr.

A refresh token works once. A used one that comes back ends the whole sign-in, because the install takes it for a stolen copy. So the CLI refreshes under a lock of its config dir. Many commands at once, in many terminals, make one refresh, and the others read the new tokens. CLI tokens, API keys, admin API keys, and SSH keys gives the rules.

Sign out

Section titled “Sign out”

logout ended the CLI sign-in on the install too, so a copy of its tokens does not work anymore. The profile keeps its URL and its active org, so hopbox login alone signs in again.

If you lose a laptop, end its sign-in from another device. Open the page “Account” of the console. The section “CLI sign-ins” lists each sign-in with the name of its client and its last use. Click “End” on the row of the lost laptop.
