Check the network of a machine

The network redesign of 2026-10-27 changes this page. hopbox leaves the vRack and the OVHcloud API, and the servers talk over their public addresses (Q90). This page still describes the current code. Milestones N26 to N32 change the code and this page. Before you set up a fleet on the vRack, read Q90.

This guide follows the network of one machine on a server with the node role. It finds the address of the machine, checks its egress and the destinations that it cannot reach, and reads its traffic counters. On an install with several servers, it also checks the mesh between the servers. The node network and the mesh describe each part.

What you need

Section titled “What you need”
  • A Linux server with the control role, the node role, and the edge role, installed as in Install hopbox on a Debian 13 server by hand. sudo hopboxd admin server list must show the server ready.
  • A running machine box1, made as in Run machines with Firecracker.
  • The hopbox CLI, signed in to the install, as in Use the hopbox CLI.
  • For the last steps, the nft tool on the server: sudo apt install nftables. hopboxd does not need it.

Set the resolvers

Section titled “Set the resolvers”

The machines use the resolvers of the server by default. To give them other resolvers, set network.nameservers in /etc/hopbox/hopboxd.toml, and restart hopboxd. A resolver on the server itself does not work, because a machine reaches no service of its node:

The running machines keep their network during the restart. A machine gets the new resolvers at its next boot.

With edge servers apart

Section titled “With edge servers apart”

Edge servers can run apart from the nodes. A node then sends the egress of its machines through an egress tunnel to one edge server (the egress of the machines). The hash of the machine address picks the edge server. So curl https://ifconfig.me in a machine prints the floating address of that edge server, and curl -6 the IPv6 address of its uplink.

On the node, list the tunnels, one for each edge server, and their rules:

When an edge server stops, the next mesh drops it, and its machines move to the other tunnel. The move waits for the unresponsive time of 20 s, a sweep of the leader, and a heartbeat of the node. The test fleet checks that it takes at most 40 s.

The sets machines, machines6, and inbound hold the tap device of each machine, each with its counter:

Do not flush the nftables ruleset of the server, and do not restart nftables.service: the machines lose their isolation for a moment. Within milliseconds, hopboxd installs the table again, ends each connection that a machine opened to the server in the gap, and logs the nftables table inet hopbox_node lost a part outside hopboxd. hopbox_node_network_repairs_total counts these repairs.

The metrics listener serves the same counters for each machine:

The inbound counter grows only with the connections that the node opened, such as a request through the machine URL. The answers to the egress of the machine do not count. Each heartbeat tells the control role which machines got inbound traffic, so these machines count as used for their auto-delete timeout.

Check the mesh

Section titled “Check the mesh”

This part needs an install with several servers, each with a peer address: the public IPv4 address at which the other servers reach it (Enrollment and the install PKI). A server without a peer address, such as a server alone on ks, stays out of the mesh. hopboxd admin server list shows the peer address of each server.

Each enrolled server has the WireGuard device hbm0. A server with a peer address also gets a mesh address in 10.239.0.0/16. The admin API shows the mesh part of each server. Run this command on a control server, with the ID of a server from sudo hopboxd admin server list:

On a server of the mesh, wg show lists one peer for each other server, at its peer address. Install the tool first with sudo apt install wireguard-tools. hopboxd does not need it.

A node has the subnets of the other nodes as routes over hbm0. An edge server has the subnet of each node. From an edge server, a TCP connection to a machine on another node goes over the mesh. Run this command on an edge server, with the address of a machine that listens on port 8000:

The machine sees the mesh address of the edge server as the source. A server without the edge role cannot open a connection to a machine, and the command times out there.

Between the peer addresses, only WireGuard packets of the mesh go between the servers, apart from the control channel and the SSH through the jump hosts. The mesh uses UDP port 51820, and the egress tunnels the ports from 51821. The metrics of the mesh show the handshake and the bytes of each peer:

A restart or an upgrade of hopboxd keeps the device, so the mesh traffic goes on. Do not manage hbm0 with another tool, such as wg-quick. hopboxd sets the device back within 2 s.

On the public interface, the host firewall takes UDP port 51820 and the ports of the egress tunnels only from the peer addresses of the servers of the install (the host firewall). A server without a peer address is not in that set. List the set, and the last copy that the server keeps on its disk:

When something fails

Section titled “When something fails”
What you see Cause and fix
hopboxd stops at its start with the host names no resolver that a machine can reach The resolv.conf of the server names only a loopback resolver. Set network.nameservers.
The log of hopboxd has the machine boots without network The machine has no address, for example on a node without the node network. Its tap device stays down.
The egress of a machine times out, but the edge reaches the machine A host with Docker drops forwarded packets in the chain FORWARD of iptables. Accept the tap devices in the chain DOCKER-USER, as in Docker on the server, or run the node without Docker.
The log of hopboxd has the nftables table inet hopbox_node lost a part outside hopboxd Something flushed the ruleset, such as a restart of nftables.service. hopboxd installed the table again. Find what flushed it, and stop it.
no capacity: the subnet ... has no free machine address The node holds 4094 machines and held addresses. Delete a machine, and wait 5 minutes for the hold of its address.
The log of hopboxd has cannot set up the mesh device. The next check tries again The kernel has no module wireguard, or another device has the name hbm0. Load the module with sudo modprobe wireguard, or remove the other device.
On a node without the edge role, each connect of a machine to the internet fails at once The node has no egress edge, so its egress fails closed. Check that sudo wg show all endpoints lists a tunnel hbe0, and that an edge server is ready in hopboxd admin server list (the egress of the machines).
The log of hopboxd has the reverse path filter is on The kernel drops the packets of the egress tunnels, and an edge server takes no egress. Set the sysctl net.ipv4.conf.all.rp_filter to 0 (the egress of the machines).
wg show hbm0 lists no peer The control role sends the mesh only to a server with a peer address whose heartbeat carries its part of the mesh. Check that hopboxd admin server get shows peer_address and mesh_address for the server. Set a missing peer address with hopboxd admin server set-peer-address (hopboxd).
