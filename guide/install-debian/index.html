Install hopbox on a Debian 13 server by hand

This guide installs hopbox on one Debian 13 server with the control role and the node role, then upgrades it and rolls it back. Serve the domain of an install with the DNS role adds the DNS role.

The hopbox Terraform provider does these steps for each server of an install (Install hopbox on an OVHcloud server with Terraform). Use this guide to try a release bundle on a test server, or to see what the provider does. An install of the hosted service gets its servers only from the provider.

The release files of hopbox are not public yet. The hopbox team gives them on request.

What you need

Section titled “What you need”
  • A Debian 13 server for amd64, with KVM and root access. The preflight check tells you what is missing (the preflight check).
  • The package of the tested host kernel 6.18.57-hopbox1, linux-image-6.18.57-hopbox1_6.18.57-1_amd64.deb, and its .sha256 file, from the release files. Step 1 installs it. With another kernel, the install goes on with a warning.
  • A free disk or partition for /var/lib/hopbox. The disks of machines need XFS with reflinks there.
  • The release bundle hopbox-v0.1.0-linux-amd64.tar.gz and its .sha256 file, from the release files. The people who work on hopbox can build them with make bundle instead.
  • A domain for the install, such as example.com.

1. Install the host kernel

Section titled “1. Install the host kernel”

The host kernel 6.18.57-hopbox1 is the kernel that hopbox tests (Host kernel). The Debian kernels stay installed as fallbacks. Copy the package and its checksum file to the server, then check the package there:

sha256sum prints linux-image-6.18.57-hopbox1_6.18.57-1_amd64.deb: OK. If it prints FAILED, do not install the package. The pin below makes it the default of GRUB, also after a later upgrade of the Debian kernel.

GRUB names each menu entry after the UUID of the root file system, so the pin uses the ID of the entry. Read the UUID first:

If echo prints nothing, stop: the pin needs the UUID. Else write the pin, and make sure that grub.cfg has the entry:

The grep prints the line of the entry. If it prints nothing, grub.cfg has no entry for the kernel. Then remove /etc/default/grub.d/20_hopbox_kernel.cfg, run update-grub again, and keep the Debian kernel.

On the tested server, SSH answered 187 to 319 seconds after the reboot.

Section titled “3. Copy and check the bundle”

Copy the bundle and its checksum file to the server, then check it there:

Section titled “4. Install”

Unpack the bundle, and run its hopboxd install as root:

The install copies the release to /opt/hopbox/releases/v0.1.0, makes the users, the dirs, the config, the first key-encryption key, and the Postgres cluster. It reserves the SSH ports, writes the systemd units, runs the preflight check, and starts hopboxd (hopboxd). It prints the preflight check, log records, and these last lines:

The Terraform provider also passes --bootstrap-admin-key-hash with the hash of the first admin API key. At its first start, the control role registers that hash as the admin API key bootstrap and removes the file (Server layout). A server that you install by hand does not need it: root makes admin keys with hopboxd admin admin-key create (hopboxd).

Check that hopboxd runs, and that the install has its domain:

systemctl status shows active (running). admin config get prints domain example.com. The log of hopboxd is in the journal: journalctl -u hopboxd.

Upgrade

Section titled “Upgrade”

Copy the new bundle and its checksum file to the server. Then run:

The upgrade unpacks the bundle to /opt/hopbox/releases/v0.2.0 and runs the install of the new release (hopboxd). That install restarts hopboxd. The running machines stay up, because they run in hopbox-machines.slice, outside hopboxd.service. The data stays: the config, the keys, the cluster, and the identity of the server.

If the new release has another major version of Postgres, the upgrade stops before the switch, and the old release keeps running. The error starts with postgres data dir /var/lib/hopbox/pg/data holds a Postgres 18 cluster. The same holds for a release that does not run with the newest schema migration of the control store (the bundled Postgres).

An install with more than one server upgrades one server at a time: first the control servers, then the edge and DNS servers, then the nodes. The hopbox Terraform provider keeps this order (hopbox Terraform provider). The release before can run beside the new one, so the servers that wait keep working.

Roll back

Section titled “Roll back”

The server keeps the previous release. To go back to it, run:

A rollback cannot undo a schema migration of the newer release. Each migration names the oldest release that runs with it. If the newer release applied a migration that does not allow the previous release, the rollback stops before the switch, and the newer release keeps running. The error starts with the control store has the schema migration. Upgrade to a release that knows the migrations instead (hopboxd).

v0.1.0 runs only on a store whose migrations it knows. So a rollback from v0.2.0 to v0.1.0 stops with that error. A rollback from a later release, such as v0.3.0, to v0.2.0 works when the migrations of v0.3.0 allow v0.2.0. Then readlink /opt/hopbox/current prints releases/v0.2.0, and readlink /opt/hopbox/previous prints releases/v0.3.0. A second rollback goes forward again.

If the install stops

Section titled “If the install stops”

The install makes every check before it changes the config, the current release, or the units. So after a refusal, fix the cause and run the same command again.

Message Fix
/var/lib/hopbox is on ext4, but the disks of machines need XFS with reflinks there Do step 2.
the preflight check failed, so this server cannot run machines Fix each failed check that the lines above it list, such as KVM in the firmware (the preflight check).
--domain is required on the first install of the control role on a server Add --domain.
/usr/local/bin has mode 0775, which lets group or others change it A Debian host that was upgraded from an old release can have the mode 2775 with the group staff there. Run sudo chmod 755 /usr/local/bin.
/opt/hopbox/releases belongs to uid 1000, ... Run sudo chown root:root on the dir that the message names.
hopboxd v0.2.0 did not start Read journalctl -u hopboxd, then run sudo hopboxd upgrade --rollback.

Server layout lists every path, user, and unit of the install.
