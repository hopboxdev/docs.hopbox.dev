First sign-in on a new install

A new install has no SMTP config and no OAuth app, and hopbox has no passwords. So the first instance admin signs in through a one-time login link that root prints on a control server. This guide signs in that way on a laptop. Then it reads the account and the audit log, and sets up magic links for everyone else.

This guide calls the API with curl, in the same way as the console does, so it shows each call. Use the console signs in with the same link in a browser.

What you need

Section titled “What you need”
  • hopboxd with the control role on a laptop, as in Run the control role on a laptop. This guide uses its bootstrap config /tmp/hb/hopboxd.toml and the API on 127.0.0.1:7080.
  • curl.
  • For magic links: an SMTP server. A local mail catcher such as Mailpit works, on 127.0.0.1:1025. Without one, use the file mail transport, as in Magic links without an SMTP server.

Print the login link

Section titled “Print the login link”

The link works once, for 15 minutes. Treat it as a password until then. The audit log records that root made it, but never the token (Sessions, cookies, and sign-in links).

On an install with an edge, you open this link in a browser (Use the console). The console page reads the token after #token= and calls VerifyLoginLink. Here, you make that call yourself.

Sign in with the link

Section titled “Sign in with the link”

Put the token in a shell variable, and call VerifyLoginLink:

The link created your account, made it an instance admin, and gave it a personal org. Your email stays unverified. So a later magic link or GitHub sign-in with the same email reaches another account (Sessions, cookies, and sign-in links). To sign in to this account with a magic link, link your email from the session (Link your email to your account).

The two headers Origin and Connect-Protocol-Version are what the console sends. Without them, the call fails with permission_denied, so no page of another site can sign a browser in. Try the link a second time, and it fails with unauthenticated: it works once.

The response sets the session cookie. The cookie has the Secure flag, so curl does not send it back over plain HTTP. Copy it from the saved headers:

The session lasts 30 days. After 7 days without a call, it ends before that (Sessions, cookies, and sign-in links).

If the SMTP server fails, the call gets unavailable, and the log of hopboxd has the record the magic link email failed with the cause.

Link your email to your account

Section titled “Link your email to your account”

The email of your login-link account is unverified, so it links no magic link. Link it from your session instead (Sessions, cookies, and sign-in links). The link needs a sign-in within the last 10 minutes. If your sign-in is older, the call fails with permission_denied. Then print a new login link, and sign in with it again as in Sign in with the link.

Use the token with the same session cookie:

The response has linked and no Set-Cookie, so your session stays. Your account now has the email link as a sign-in method, and the email is verified. A magic link to root@example.org now signs in to this account. Without the session cookie, the call fails with permission_denied, and the link stays unused: only the session that asked for the link can use it.

Keep a second instance admin

Section titled “Keep a second instance admin”

An install keeps at least one instance admin, so admin instance-admin revoke refuses the last one. Make a second admin first, for example the account of Ann, by her verified email:

Root on a control server can always print a new login link, or grant the role again. So a lost session never locks the operator out.

Sign out

Section titled “Sign out”

The response clears the cookie, and the session ends. The next call with the old cookie runs as an anonymous caller, and a call that needs a credential gets unauthenticated.
