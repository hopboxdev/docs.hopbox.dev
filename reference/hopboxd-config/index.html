The bootstrap config of hopboxd

The bootstrap config holds the few settings that hopboxd needs before it can reach the control store: its roles, its dirs, its listeners, and the address of the control role. hopboxd run reads it (hopboxd). The settings of the whole install, such as its domain, live in the control store and change through the admin API (the admin API). The code is in internal/config.

File

Section titled “File”
Item Value
Path /etc/hopbox/hopboxd.toml. hopboxd run --config gives another path.
Format TOML
Encoding UTF-8

hopboxd install writes the file (hopboxd). It sets roles from --roles, and channel.control_urls (or the old key channel.control_url) and channel.labels from --control-url and --label. With one --control-url, it writes the old key channel.control_url, unless the file has channel.control_urls already. So a rollback to a hopboxd from before control_urls, which refuses that key, still reads the file. With more than one --control-url, it writes channel.control_urls and deletes channel.control_url. It keeps every other key of a file that exists, and writes a file with the mode 0644. Before it reads a file that exists, it makes the owner and mode checks below. So root never takes values from a file that another user can change.

hopboxd run reads the file once, at start. A change takes effect at the next start. An install that changes the file restarts hopboxd. hopboxd admin reads it to find the admin socket (hopboxd). hopboxd enroll and hopboxd preflight read it for the roles, the data dir, and the control URLs (hopboxd).

The file names the Postgres binaries that hopboxd runs and the external Postgres that it trusts, so a hopboxd that runs as root refuses a file that another user can change:

  • The file must be a regular file of at most 64 KiB.
  • As root, the path must not be a symlink. hopboxd opens it with O_NOFOLLOW.
  • As root, the file must belong to root.
  • As root, group and others must not be able to write the file. Mode 0644 or 0600 is fine.
  • As root, the dir of the file, such as /etc/hopbox, must be a real dir, not a symlink. It must belong to root, and group and others must not be able to write it. Otherwise another user can swap the file. hopboxd checks only this dir, not the dirs above it, such as /etc. The install owns /etc/hopbox, and the OS owns the dirs above it.

Keys

Section titled “Keys”
Key Type Default Description
roles array of strings none, required The roles of this server: control, node, dns, edge, or more than one. Each role appears at most once. The control role runs the control store, the API, the internal listener, and the admin socket. The node role runs machines. The DNS role answers DNS queries for the zones of the install (the DNS role). The edge role serves HTTPS for the domain of the install and for every machine URL (the edge role). It also runs the SSH front door of the machines (the SSH front door). A server with a role other than control enrolls with the control role. It keeps a control channel to it (the control channel).
data_dir absolute path /var/lib/hopbox The state of the server. The bundled Postgres keeps its cluster in <data_dir>/pg (the bundled Postgres), the file keyring keeps its key-encryption keys in <data_dir>/kek (Sealing), and an enrolled server keeps its identity in <data_dir>/server (Enrollment and the install PKI). The control role keeps the mail of the file mail transport in <data_dir>/mail (Mail). The reflink check of the preflight check runs in this dir (the preflight check). The node role keeps its images, kernels, disks, and jails here (the Firecracker driver). On a server with the node role, the path has at most 25 characters, because each jail holds unix sockets. hopboxd and hopboxd install refuse a longer path with data_dir: "<path>" has <n> characters. With the node role, it has at most 25, because each jail in it holds unix sockets.
run_dir absolute path /run/hopbox The sockets of the server. The bundled Postgres has its socket in <run_dir>/pg, and the admin socket is <run_dir>/admin.sock (the admin API).
control.api_listen host:port 127.0.0.1:7080 The TCP address of the API listener of the control role (the API server). The host must be a loopback IP address, such as 127.0.0.1 or [::1]. Port 0 picks a free port.
control.internal_listen host:port 127.0.0.1:7443 The TCP address of the internal listener of the control role, which serves the cluster API over TLS to the servers of the install (the internal listener). The host must be an IP address, of any kind, such as 127.0.0.1 or 10.0.0.5. 0.0.0.0 listens on every address. Port 0 picks a free port. It must differ from control.api_listen, except when both use port 0. With several control servers, use the vRack IP of the server, because the other control processes reach this listener at the address that it names. A listener on every address gets no forwarded data streams (the internal listener).
control.release_image absolute path /opt/hopbox/current/image/artifact.json The artifact.json of the default image of the release. At each start, the control role registers this image, unless the install has it already or has an image of the same name from a newer release (hopboxd). A missing file gives a log record at level info, and a file that is not valid gives one at level error. In both cases, the start goes on.
channel.control_urls array of URLs ["https://127.0.0.1:7443"] The URLs of the internal listeners of the control servers. List 1 to 8 URLs, each one once. A server with a role other than control enrolls at the first URL that answers (Enrollment and the install PKI). It keeps one control channel, to one URL at a time. The first channel goes to the URL that a CRC-32 of the server ID picks, so the channels of a fleet spread over the control servers. After a lost or refused channel, the next dial goes to the next URL of the list (the control channel). Once the control role sends the URLs of the live control servers on the channel, the server keeps them in <data_dir>/server/control-urls, and dials them before the URLs of this key (the control channel). So this list needs to name only one control server that is up at the first start. The edge role also sends the requests of the API and the console to these URLs, in turn (the edge role). Each URL must be an https URL of a host, with an optional port, and without user info, a path other than /, a query, or a fragment. Without a port, the port is 443. On a server that also has the control role, a URL names the internal listener of the same hopboxd.
channel.control_url URL none The old key of channel.control_urls with one URL. hopboxd moves its value into channel.control_urls when it reads the file. A file with both keys fails (Errors).
channel.labels table of strings empty The labels of the server, for example zone = "gra". Each heartbeat reports them, and the registry keeps them (the control channel), until an instance admin sets the labels through the admin API. From then on, the registry keeps the labels of the admin (the admin API). At most 64 labels. A key has 1 to 63 characters of a-z, 0-9, ., _, and -, and starts with a lowercase letter. A value is valid UTF-8 of at most 255 bytes, without control characters.
dns.listen array of host:port [":53"] The addresses of the DNS role (the DNS role). It listens on UDP and on TCP at each address. List 1 to 16 addresses, each one once. The host is empty, which listens on every address, or an IP address, such as 203.0.113.10. A host name is refused. The port is a number. Port 0 picks a free port, and UDP and TCP share that port. The DNS role opens its sockets at the start of hopboxd run, so a port that another program holds fails the start (hopboxd). On Linux, an address that the server does not hold yet, such as the address of edge.public_ipv6, passes, and takes queries once it exists (the DNS role).
edge.https_listen host:port :443 The address of the HTTPS listener of the edge role (the edge role). The host is empty, which listens on every address, or an IP address, such as 203.0.113.10. A host name is refused. Port 0 picks a free port. The edge role opens the listener at the start of hopboxd run, so a port that another program holds fails the start (hopboxd).
edge.http_listen host:port :80 The address of the plain HTTP listener of the edge role. It answers each request for a host of the install with a redirect to HTTPS (the edge role). The rules of edge.https_listen apply. The two addresses must differ. Only port 0 can appear in both.
edge.ssh_listen host:port :2222 The address of the listener of the SSH front door (the SSH front door). The rules of edge.https_listen apply. Its port must be outside the SSH ports 10000 to 30000, and it must differ from the two HTTP listeners. Only port 0 can appear twice. With edge.ssh_redirect, the host must be empty or ::. The redirect sends each connection to the address of the network interface that took it. So a listener on one address, such as a floating IP, gets no client, and 0.0.0.0 gets no IPv6 client.
edge.ssh_redirect bool true Makes hopboxd replace the nftables table inet hopbox_edge at the start of the edge role. The table sends every TCP connection to a port from 10000 to 30000 of the server to edge.ssh_listen (the SSH front door). A stop deletes it. On a system without nftables, such as macOS, the edge role logs a warning and serves only edge.ssh_listen, which reaches no machine. If the operator makes the redirect, set it to false.
edge.public_ipv6 IPv6 prefix none The public IPv6 address of this edge server in the IPv6 block of the install, with the prefix length of the block, such as 2001:db8:0:100::11/56. The block lives in the vRack, so hopboxd keeps the address on the vRack interface, with the routing table hopbox_egress6 (the edge role). The address is a global unicast address, not a unique local one, and not the first address of its block. The block is from /48 to /64. Only a server with the role edge takes the key, and only with edge.public_ipv6_gateway. A hopboxd before this key refuses the file, so add it only after the upgrade of the server.
edge.public_ipv6_gateway IPv6 address none The gateway of the IPv6 block on the vRack, such as 2001:db8:0:100::1. It is the default route of the table hopbox_egress6. It is a link-local address, such as fe80::1, or an address of the block of edge.public_ipv6, other than its first address and other than the address of the server.
acme.name_servers array of host:port empty The addresses at which the ACME job of the control role checks that each name server serves a change of the zone (the certificate of the install). Empty means port 53 at the addresses of ns1 and ns2 of the zone. At most 16. Each host is an IP address. A host name is refused. When the DNS role listens on another port, set it, such as ["127.0.0.1:15353"] on a laptop.
acme.ca_file absolute path empty A PEM file of more root certificates for the HTTPS of the ACME directory. The ACME job trusts them, for example the root of the test CA Pebble (the certificate of the install). Empty means the roots of the system only. A file that does not load, or holds no certificate, fails the start of hopboxd run.
postgres.install absolute path /opt/hopbox/current/postgres The bundled Postgres: a dir with bin/, lib/, and share/ (the bundled Postgres). hopboxd admin db export runs pg_dump and pg_restore from it (hopboxd).
postgres.user string hopbox-pg The OS user that runs Postgres when hopboxd runs as root (the bundled Postgres).
postgres.url URL empty An external Postgres for the control store, such as managed PostgreSQL (the bundled Postgres). With it, the control role starts no bundled Postgres and connects over TLS. The form is postgres://<user>@<host>[:<port>]/<database>?sslmode=verify-full. The scheme can also be postgresql. It must name one host, a user, and a database, and have sslmode=verify-full. It must not hold a password, or the parameters password, passfile, sslrootcert, sslcert, sslkey, sslpassword, sslcertmode, service, servicefile, host, hostaddr, port, dbname, or user. Other parameters of libpq and pgx, such as connect_timeout, pass on. It needs postgres.ca_file and postgres.password_file.
postgres.ca_file absolute path empty The PEM file of the CA that signed the certificate of the external Postgres. hopboxd checks the certificate against it, and the host name of postgres.url against the certificate. For managed PostgreSQL, it is the CA certificate that OVHcloud gives for the service. It needs postgres.url. As root, hopboxd makes the owner and mode checks of the bootstrap config on it.
postgres.password_file absolute path empty A file that holds the password of the user of postgres.url, on one line. A newline at the end is fine. It needs postgres.url. As root, the file must belong to root, must not be a symlink, and group and others must not read or write it: mode 0400 or 0600. Its dir has the checks of the dir of the bootstrap config. At most 4 KiB.
metrics.listen host:port 127.0.0.1:9464 The TCP address of the Prometheus metrics (Metrics). The host must be a loopback IP address. Every role uses it.
vmm.firecracker absolute path /opt/hopbox/current/firecracker/firecracker The Firecracker binary of the node role (the Firecracker driver). Its file name must be firecracker, because the jailer names the jail of each machine after it. Each boot uses the file at this path, so an upgrade moves new boots to the Firecracker of the new release. A running microVM keeps its own copy. The compatibility class takes its snapshot format version (the control channel).
vmm.jailer absolute path /opt/hopbox/current/firecracker/jailer The jailer binary of the node role. The unit of each machine runs it (the Firecracker driver).
vmm.kernel absolute path /opt/hopbox/current/kernel/vmlinux The guest kernel of the release. At each start, hopboxd run adds it to the kernel cache (the Firecracker driver). A missing file gives a warning, and the start goes on.
network.nameservers array of IPv4 addresses empty The resolvers of the machines of the node role, at most 3, each once (the node network). The guest agent writes them to /etc/resolv.conf of each machine, and the machines reach them on port 53. Empty takes the IPv4 resolvers of the host, from /run/systemd/resolve/resolv.conf or /etc/resolv.conf. A loopback, unspecified, link-local, or multicast address, or an address of the install range 10.240.0.0/12, is refused. A resolver on the node itself does not work, because a machine reaches no service of its node.

The API listener has no TLS. So hopboxd refuses a control.api_listen that is not a loopback address, and the API never leaves the server in clear text. A host name, even localhost, is refused, because a name can resolve to an address that is not loopback. The internal listener has TLS, and every call on it except Enroll needs a server certificate, so control.internal_listen can be any IP address. On an install with one server, it stays on 127.0.0.1. hopboxd refuses a host name there too.

hopboxd checks the keys of [postgres] on every server, but only the control role uses them. hopboxd run reads postgres.ca_file and postgres.password_file at its start, so a change of either file takes effect at the next start. hopboxd checks the keys of [control] only on a server with the control role. It checks the keys of [channel] only on a server that enrolls: one with a role other than control. It checks the keys of [dns] only on a server with the DNS role. It checks the keys of [edge] only on a server with the edge role. It checks the keys of [acme] only on a server with the control role. It checks the keys of [vmm] and [network] only on a server with the node role.

The old name [node]

Section titled “The old name [node]”

Before the DNS role, [channel] had the name [node]. This release still reads [node] as [channel], and the next release refuses it. With [node], hopboxd run logs this record at level warn, with the path of the file in config:

hopboxd enroll prints the same warning on stderr, after hopboxd: warning: . When hopboxd install writes the file, it renames [node] to [channel]. An error about a key of [node] names the key under channel, such as channel.labels. A file with both sections is refused.

The paths of the sockets have a limit: a unix socket path has at most 103 bytes on macOS. So keep run_dir short. The admin socket needs 11 bytes more for its temp name (the admin API).
