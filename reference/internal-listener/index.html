The internal listener

The internal listener is the TLS listener of the control role for the servers of the install. New servers enroll on it (enrollment.md), and enrolled servers keep their control channel on it (control-channel.md). The edge servers call EdgeService on it, and send it the requests of the clients of the API and the console (edge.md). The code is in internal/control and internal/api.

Listener

Section titled “Listener”
Item Value
Address control.internal_listen of the bootstrap config, by default 127.0.0.1:7443 (hopboxd-config.md)
Address rules An IP address and a port. A host name, even localhost, is refused. Any IP address works, also one that is not loopback. Port 0 picks a free port.
Transport TLS 1.3 only
HTTP versions HTTP/2 and HTTP/1.1, picked with ALPN
HTTP/2 frames At most 64 KiB for each frame that a peer sends. A client of HTTP/2 holds a buffer of that size for each request body that it streams. So the edge holds 64 KiB for each request that it forwards, not 512 KiB.
Protocols Connect, gRPC, and gRPC-Web, with the binary protobuf and JSON codecs. ControlService takes no gzip: a request in gzip fails with unimplemented and the message unknown compression "gzip", and no response uses gzip (control-channel.md). The other services of the listener take gzip and answer in it.
Services hopbox.cluster.v1.EnrollmentService, hopbox.cluster.v1.ControlService, hopbox.cluster.v1.EdgeService, gRPC reflection, and gRPC health. A forwarded request reaches the public API instead. See Forwarded requests.
Server certificate the control certificate of the install CA, with the URI SAN hopbox://control (enrollment.md)
Client certificate asked for in every handshake. A client can send none. A certificate that it sends must chain to the install CA and allow client auth, or the handshake fails.
Unit internal listener, after api and before admin socket (hopboxd.md)
Stop timeout 5 s. A stop ends every open stream at once, so every control channel ends (api.md).
Metrics the label listener="internal" for the cluster API, and listener="edge" for the forwarded requests (metrics.md)

On an install with one server, the listener stays on 127.0.0.1, and the channel unit of the same server dials it on loopback. In phase 2, it listens on the vRack IP of the control server, so the other servers can reach it.

The HTTP server has the timeouts and limits of the API listener (api.md): the header read timeout, the body read timeout of a unary call, the idle timeout, and the largest request message of 4 MiB.

Before the first key-encryption key

Section titled “Before the first key-encryption key”

The certificate of the listener comes from the install CA, and the CA needs a key-encryption key to seal its key (enrollment.md). A fresh install has no such key. So the listener starts without a certificate, and logs this warning:

Until then, each TLS handshake fails, and the HTTP server logs http: TLS handshake error from <peer>: the internal listener has no certificate: ... with component=http. hopboxd install makes the first key-encryption key, so a server that it set up never logs this. On another server, run sudo hopboxd admin kek rotate (hopboxd.md). The next handshake then makes the CA and the certificate, without a restart.

Any other failure to read the CA stops the start of the unit.

Callers

Section titled “Callers”

The request gate of the listener has one resolver, the server-certificate resolver (api.md):

Case Caller
The connection has no client certificate. anonymous
The certificate passes the checks of enrollment.md. server, with the ID of the server
The certificate fails those checks, for example its serial is unknown or its server is decommissioned. none. The call ends with unauthenticated and the message the credential is not valid.

Every procedure of the listener needs a server certificate, except EnrollmentService.Enroll, whose enrollment token is its credential. An anonymous call of another procedure ends with unauthenticated and the message this call needs a server certificate. This rule runs after the gate and before the policy check. So it covers health and reflection too, which the policy allows for every caller on the other listeners.

Procedure Without a certificate With a server certificate
EnrollmentService.Enroll allowed allowed
ControlService.Channel, ControlService.AttachStream unauthenticated allowed for the server itself (control-channel.md)
EdgeService.ExchangeMachineCode, EdgeService.AuthorizeMachineRequest, EdgeService.AuthorizeSSH unauthenticated allowed for a server whose certificate carries the role edge. Another server gets permission_denied.
grpc.health.v1.Health, reflection unauthenticated allowed

EdgeService

Section titled “EdgeService”

hopbox.cluster.v1.EdgeService serves the sign-in of private machine URLs (edge.md) and of the SSH front door (ssh-front-door.md) to the edge servers. Each call needs the certificate of a server with the edge role.

Procedure Policy action Description
/hopbox.cluster.v1.EdgeService/ExchangeMachineCode server.exchange_machine_url_code Trades the one-time code of a private machine URL for the token of the cookie __Host-hopbox_machine of that URL. The code works once, within 60 s, and only for its machine. The new token replaces any older token of the same console session and machine.
/hopbox.cluster.v1.EdgeService/AuthorizeSSH server.authorize_ssh Checks that the account of an SSH key can open a shell, as a Linux user, in the machine of an SSH port now. Each answer that allows also records a use of the machine. The request, the response, and the rules are in ssh-front-door.md.
/hopbox.cluster.v1.EdgeService/AuthorizeMachineRequest server.authorize_machine_url Checks that the account of a token can open the private URL of the machine now. Each answer that allows also records a use of the console session, as a call of the console does (sessions.md).
Message Field Type Description
ExchangeMachineCodeRequest machine string The name of the machine of the host of the request, such as box1 for box1.example.com.
ExchangeMachineCodeRequest code string The code of the query of the request.
ExchangeMachineCodeResponse token string The value of the cookie __Host-hopbox_machine, valid only for that machine.
AuthorizeMachineRequestRequest machine string The name of the machine of the host of the request.
AuthorizeMachineRequestRequest token string The value of the cookie __Host-hopbox_machine.
AuthorizeMachineRequestResponse machine_id string The ID of the machine, a UUID.
AuthorizeMachineRequestResponse account_id string The account of the token, a UUID.
AuthorizeMachineRequestResponse valid_for google.protobuf.Duration How long the edge can keep the answer: at most 1 minute, and never past the end of the console session. A change event of the access ends it sooner (control-channel.md).

AuthorizeMachineRequest checks four rules. Each must hold:

  • The token names a row of machine_url_sessions, and the console session of that row lives: its absolute end and its idle end are ahead (control-store.md, sessions.md).
  • The machine of the request holds its name, its target is not deleted, and it is the machine of the token.
  • The account uses the machine, under the policy action machine.open_url: it is the creator of a private machine, or a member of the org of a shared one (api.md). An org admin does not open the private machine of another member.
  • An instance admin did not suspend the org of the machine.
Code Message Cause
unauthenticated the sign-in of the machine URL is not valid: ... The code or the token is malformed, unknown, used, expired, replaced, or for another machine, or its console session ended. The machine can also be gone. The edge starts the sign-in again.
permission_denied permission denied: ... The account has no access to the machine now. Another server than an edge server gets it too.
failed_precondition failed precondition: org suspended: an instance admin suspended the org of the machine The org of the machine is suspended.
invalid_argument invalid argument: ... The machine name is not a valid name (domain-rules.md).

Forwarded requests

Section titled “Forwarded requests”

The edge servers forward the requests of the domain of the install to this listener, over the mutual TLS of their server certificates (edge.md). Each forwarded request carries the header Hopbox-Client-Addr with the address of the client, IP:port. The edge sets the header on each request, over any value that the client sent.

The listener splits the requests by this header:

  • A request without the header reaches the cluster API, as in Callers.
  • A request with the header reaches the public API and the admin API, as on the API listener (api.md). The plain HTTP routes under /auth/ and the WebSocket of exec are there too. So a forwarded request never reaches the cluster API with the certificate of the edge server.

Before it serves a forwarded request, the listener checks the certificate of its connection. The certificate must pass the checks of enrollment.md. It must also carry the role edge, under the policy action server.forward_requests. The listener keeps a passed check for 5 s, by the serial of the certificate. So each request does not cost a read of the control store. It keeps at most 1024 checks. So a decommission or a retired certificate stops the forwards within 5 s. Then the address of the header becomes the peer of the request, and the header goes. The request gate, the rate limits, and the logs see the address of the client. The credentials of the request, such as the session cookie or an API key, prove its caller. The certificate of the edge server proves no caller. Only this check trusts a client address: no listener reads X-Forwarded-For.

Status Body Cause
403 only a server with the edge role forwards the requests of clients The connection has no TLS client certificate, or the certificate is refused, or its server has no edge role. The listener logs forwarded request refused at level warn, with peer and err.
503 the server failed to check the credential. Retry later The check of the certificate failed, for example on a failure of the control store. The listener logs forwarded request check failed at level error, with peer and err.
400 the header Hopbox-Client-Addr must hold one IP:port The header has more than one value, or a value that is not an IP address and a port.

The forwarded requests get the label listener="edge" in the metrics of the API. Each forwarded call also gets the access log record api call (api.md).
